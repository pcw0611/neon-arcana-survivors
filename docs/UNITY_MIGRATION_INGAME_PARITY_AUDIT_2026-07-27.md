## 1. 결정

기존 3단계 문서는 타이틀, 전투 시작 직후, 첫 강화 선택과 일부 기술 계약을 기준으로
구현 완료를 선언했다. 사용자 검수에서 도감과 월드 스크롤이라는 기본 플레이 경험이
원작과 다르거나 빠진 사실이 확인됐으므로 이 완료 판정을 철회한다.

앞으로는 원작의 기능 이름이 Unity에 존재하는지만 확인하지 않는다.
각 기능을 다음 다섯 축으로 나누어 웹판과 Unity판을 일대일로 대조한다.

1. 동작: 같은 입력과 상태에서 같은 결과가 나오는가
2. UI: 같은 정보와 선택지가 같은 흐름으로 제공되는가
3. 데이터: 항목, 수치, 잠금, 등급, 레벨이 보존되는가
4. 연출: 이동감, 타격감, 애니메이션, 피드백이 보존되는가
5. 상태: 일시 정지, 보상 대기, 재개, 저장이 같은 규칙으로 이어지는가

사용자는 원작의 모든 기능을 하나씩 명시할 의무가 없다.
“마이그레이션”과 목표 유사도 80~90%라는 주문은 원작 전체를 기준판으로 삼으라는 뜻이다.
누락을 발견하고 목록화하는 일은 구현자의 책임이다.

## 2. 이번 재감사에서 확인한 실패 원인

### 2.1 플레이 표본이 너무 짧았다

기존 확인은 타이틀, 전투 시작 직후, 첫 강화 선택에 집중됐다.
Unity 전투 자동 캡처도 시작 후 약 1.67초 시점이어서 장거리 이동 시 드러나는
맵 스크롤 문제를 발견할 수 없었다.

도감, 일시 정지 메뉴, 유물 교체, 보스전, 전직, 특수 지역, 게임 종료까지 이어지는
전체 플레이 흐름을 통과하지 않았다.

### 2.2 기술 검증을 원작 동등성 검증으로 잘못 사용했다

기존 자동 검사는 빌드 성공, 프리팹 존재, 이동 패드 수, 자동 공격 방향 등을 확인했다.
다음 질문은 검사하지 않았다.

- 30초 이상 이동했을 때 배경 타일과 월드 그리드가 실제로 스크롤되는가
- 도감에 술식·유물·전직의 모든 카드와 현재 상태가 표시되는가
- 보상 선택 중 다른 메뉴가 충돌 없이 차단되는가
- 유물 교체·분해·중첩 흐름이 원작과 같은가
- 보스 패턴, 경고, 피격 효과, 카메라 반응이 같은가
- 전직과 마스터리의 전용 효과가 실제 전투에서 같은가

### 2.3 자체 구현을 자체 기준으로 검사했다

Unity 코드가 작성된 의도대로 실행되는지는 확인했지만,
그 의도 자체가 웹판과 같은지는 충분히 검사하지 않았다.
이 때문에 배경이 플레이어를 따라가도록 만든 잘못된 구조도 정상 동작으로 처리됐다.

### 2.4 완료 보고가 너무 빨랐다

“일부 기술 계약 통과”와 “마이그레이션 단계 완료”를 분리하지 않았다.
앞으로 사용자 승인 전 상태는 `구현 중`, `기술 검증 통과`, `유사도 미승인` 중 하나로만 표기한다.

## 3. 즉시 확인된 실제 결함

### 3.1 월드 스크롤

웹판 `drawWorld()`는 플레이어의 월드 좌표 `S.x`, `S.y`로 다음을 계산한다.

- 사이버 도시 이미지를 860px 타일로 반복
- 플레이어 이동량에 따라 타일 오프셋 변경
- 월드 좌표 기반 72px 그리드 이동
- 화면 중앙과 플레이어 월드 좌표 사이의 카메라 변환
- 적, 투사체, 보석, 상자, 위험 지대에 같은 변환 적용

현재 Unity `CameraFollow.LateUpdate()`는 카메라와 함께 배경도 플레이어 위치로 옮긴다.

```csharp
transform.position = new Vector3(Target.position.x, Target.position.y, -10f);
background.transform.position = new Vector3(Target.position.x, Target.position.y, 2f);
```

플레이어와 배경의 상대 위치가 항상 같으므로 배경 이동이 보이지 않는다.
단일 스프라이트 한 장만 사용하고 월드 그리드와 반복 타일도 없다.

판정: **동작 실패 / 연출 실패 / 3단계 필수 재작업**

2026-07-27 P0 재작업에서 기존 배경 추적 코드를 제거하고
Cinemachine 추적 카메라, 5×5 반복 도시 타일, 월드 좌표 그리드를 구현했다.
플레이어를 `(18, 9)`로 이동하는 Play Mode 검사와 Windows 캡처를 통과했다.
기술 상태는 `구현·검증 통과 / 사용자 체감 승인 대기`로 갱신한다.

### 3.2 도감

웹판 도감은 독립 화면이며 다음 세 탭을 제공한다.

- 술식: 전체 강화, 현재 랭크, 최대 랭크, 잠금, 마스터리, 한계돌파
- 유물: 전체 유물, 희귀도, 보유 여부, 현재 레벨, 현재 효과
- 전직: 전체 전직, 난이도, 설명, 현재 전직 상태

현재 Unity 도감은 다음 세 줄과 최근 런 텍스트만 출력한다.

```text
유물 도감 n/21
전직 기록 n/5
최고 점수
```

콘텐츠 카탈로그가 존재하더라도 이를 열람하고 비교할 카드 UI와 탭 상태가 없다.
웹판의 `▤ 도감` 대신 의미가 다른 작은 `☰` 버튼을 사용한다.

판정: **UI 실패 / 데이터 표현 실패 / 상태 표현 실패 / 전면 재구현**

2026-07-27 P0 재작업에서 `CodexView`와 `CodexCard.prefab`을 추가했다.
술식 27개, 유물 21개, 전직 5개를 각각 독립 탭에서 표시하며 현재 랭크,
희귀도·발견·보유 레벨, 전직 기록·활성 상태를 구분한다.
Play Mode에서 세 탭의 카드 수 `27/21/5`를 전환하며 검사했다.
기술 상태는 `구현·검증 통과 / 사용자 체감 승인 대기`로 갱신한다.

## 5. 당분간의 작업 범위

사용자 지시에 따라 당분간 **인게임만 수정한다**.

### 5.1 포함

- 이동, 조준, 자동 공격과 전투 규칙
- 카메라, 무한 월드 타일, 그리드, 스크롤
- HUD, 도감, 게임 메뉴, 선택 화면, 게임 종료 화면
- 강화, 마스터리, 한계돌파
- 유물 획득, 중첩, 교체, 분해, 보상 큐
- 전직과 전용 메커니즘
- 일반 적, 보스, 보스 옵션과 공격 예고
- 사이버 리바이어던, 내부 던전, 길들인 보스 동료
- 인게임 오디오, VFX, 파티클, 애니메이션, 카메라 피드백
- 인게임 성능을 위한 풀링과 탐색 최적화

### 5.2 후순위로 이동

- Cloudflare D1와 온라인 랭킹 API
- 서버 인증, 서버 저장, 클라우드 동기화
- 웹판 재배포와 호스팅 변경
- GitHub Release 실행 파일 배포
- Android Release/AAB 서명과 스토어 등록
- APK 전달과 에뮬레이터·실기기 반복 배포
- CI/CD와 자동 배포 파이프라인
- 온라인 운영 도구와 분석
- 다국어·타이틀·온라인 랭킹 화면의 추가 폴리싱

후순위 항목은 삭제한 것이 아니다. 인게임 동등성이 승인될 때까지 착수하지 않는다.

## 6. 재작업 순서

### P0 — 플레이 경험의 뼈대

1. 월드 스크롤, 반복 도시 타일, 월드 그리드
2. 플레이어 이동과 카메라 추적 체감
3. 도감 3개 탭과 전체 카드
4. HUD, 게임 메뉴, 보상 큐의 상태 충돌 제거
5. 강화·유물·게임 종료 흐름의 원작 동등성

### P1 — 콘텐츠와 전투 체감

## 7. 서드파티·공식 패키지 도입 권한과 판단

사용자는 특정 패키지를 하나씩 지명하지 않아도 된다고 명시했다.
구현자는 코드 구조와 게임 콘셉트를 보고 개발 시간, 품질, 유지보수 비용에 이득이 있으면
무료 또는 라이선스가 명확한 라이브러리·플러그인·에셋을 판단해 도입할 수 있다.

무조건 많이 설치하지는 않는다. 다음 조건을 모두 만족할 때 도입한다.

- 현재 인게임 문제를 구체적으로 줄인다.
- 직접 구현보다 테스트와 유지보수 비용이 낮다.
- Unity 6000.5.1f1과 호환된다.
- 라이선스와 출처를 저장소에 기록할 수 있다.
- Android 빌드 크기와 런타임 성능에 과도한 부담을 주지 않는다.
- 제거하거나 교체할 경계가 명확하다.

### 7.1 현재 코드 기준 결정

| 도구 | 판단 | 근거 |
|---|---|---|
| TextMesh Pro | **도입** | 현재 UGUI 2.5.0에 포함돼 있으나 프로젝트 UI는 구형 `UnityEngine.UI.Text` 45개 참조를 사용한다. 도감 카드, 한글 가독성, 외곽선, 글로우, 자동 크기 조절에 직접 이득이 있다. 별도 패키지 설치보다 TMP 리소스와 한글 폰트 에셋 준비가 필요하다. |
| DOTween Free 1.3.030 | **계속 사용** | 이미 설치됐다. 메뉴·카드·알림·도감 전환과 짧은 전투 피드백에 사용하되 판정과 게임 규칙에는 사용하지 않는다. |
| Cinemachine 3.1.7 | **도입** | 현재 카메라는 단순 추적 8줄뿐이고 감쇠·흔들림·줌·보스 연출이 없다. 직접 기능을 누적하는 것보다 패키지를 사용하는 편이 구현·테스트 비용이 낮다. 무한 타일 자체는 Cinemachine이 아니라 별도 월드 컴포넌트가 담당한다. |
| UniTask | **현재 보류** | 현재 런타임에 `async`, 코루틴, 비동기 로딩, 서버 요청이 없다. Unity 6에는 기본 `Awaitable`도 있으므로 지금 설치하면 이득 없이 의존성만 늘어난다. 비동기 씬·에셋·오디오 로딩이 실제로 생길 때 재평가한다. |
| Unity Input System | **현재 보류** | 입력 구조 재작성 비용과 회귀 위험이 있다. P0 이동·드래그 동등성은 현재 입력 계층을 먼저 고친다. 멀티터치와 리바인딩 요구가 커지면 전환한다. |
| Addressables | **현재 보류** | 현재 에셋 규모와 단일 씬에서는 `Resources` 교체 비용이 더 크다. 특수 지역·오디오 번들이 커질 때 재평가한다. |
| 외부 풀링 라이브러리 | **도입하지 않음** | 투사체·적·보석 풀과 공간 해시가 이미 있다. 교체 이득보다 회귀 위험이 크다. |
| Odin Inspector 등 유료 에디터 도구 | **도입하지 않음** | 현재 문제는 Inspector 편의가 아니라 원작 동등성 누락이다. 라이선스 비용도 발생한다. |

패키지를 실제 추가할 때마다
[`THIRD_PARTY_NOTICES.md`](THIRD_PARTY_NOTICES.md)에 버전, 출처, 라이선스, 사용 범위를 기록한다.

## 8. 단계 종료 게이트

다음 자료가 모두 있어야 3단계를 다시 완료로 표시한다.

1. 웹판 전체 인게임 기능표와 Unity 대응 코드·프리팹 연결
2. 30초 이상 한 방향 이동한 월드 스크롤 비교 영상 또는 연속 캡처
3. 도감 술식·유물·전직 각 탭의 동일 상태 비교
4. 강화, 유물 획득·교체·분해, 전직 선택 비교
5. 일반 적 6종과 보스 4종의 행동 비교
6. 리바이어던·내부 던전·동료 보스 비교
7. 동일 조건의 게임 종료와 런 결과 비교
8. 콘솔 예외, Missing Script, 상태 정지·재개 오류 없음
9. 사용자 체감 유사도 승인

자동 테스트 통과만으로는 완료 처리하지 않는다.
배포·서버 연결 여부도 인게임 마이그레이션 완료 판정에 포함하지 않는다.
