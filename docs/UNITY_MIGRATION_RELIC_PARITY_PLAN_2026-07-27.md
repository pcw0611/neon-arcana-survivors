## 2. 확인된 구조 차이

최신 웹판의 실제 보상 경로는 유물 세 장을 사용자가 고르는 방식이 아니다.
보상 출처와 티어를 받아 슬롯머신처럼 후보를 순환 표시한 뒤 유물 하나를 자동 확정한다.

현재 Unity는 다음과 같이 다르다.

| 항목 | 웹판 | 현재 Unity |
|---|---|---|
| 보상 데이터 | `source`, `tier` 포함 | `RewardType.Relic`만 저장 |
| 희귀도 | 생존 시간별 7구간 확률표 | 0~2 난수와 시간 보정 |
| 보스 보정 | 티어별 최소 희귀도와 승급 확률 | 없음 |
| 보물 보정 | 26% 승급 확률 | 보물 콘텐츠 없음 |
| 빌드 친화도 | 유물 태그 가중치 | 없음 |
| 신규 보정 | 신규 1.35, 중복 1.18 | 없음 |
| 표시 | 18회 슬롯 순환 후 결과 | 유물 3장 선택 |
| 중복 | 자동 레벨업 | 선택 후 레벨업 |
| 빈 슬롯 | 자동 장착 | 선택 후 장착 |
| 가득 찬 슬롯 | 레벨 우선·희귀도 보조로 최약 유물 자동 교체 | 임의 계산한 최약 유물과 분해 선택 |
| 결과 확인 | 터치 또는 아무 키를 눌러 닫기 | 즉시 다음 보상 진행 |

과거의 `renderRelicChoices()`, 교체 미리보기, 분해 UI 함수도 웹 파일에 남아 있지만
현재 `processRewards()`가 호출하는 경로는 `openRelicReward()`다. 따라서 단순히 파일에
함수가 존재한다는 이유로 구형 3장 선택 흐름을 원작 기준으로 채택하면 안 된다.

## 3. 희귀도 규칙

시간별 기본 가중치는 웹판 값을 그대로 사용한다.

| 생존 시간 | 일반 | 레어 | 유니크 | 전설 | 신화 |
|---:|---:|---:|---:|---:|---:|
| 0~59초 | 62 | 27 | 9 | 2 | 0 |
| 60~119초 | 48 | 29 | 17 | 5.5 | 0.5 |
| 120~179초 | 35 | 30 | 23 | 10 | 2 |
| 180~299초 | 23 | 28 | 29 | 16 | 4 |
| 300~479초 | 13 | 23 | 31 | 25 | 8 |
| 480~719초 | 6 | 17 | 30 | 32 | 15 |
| 720초 이상 | 2 | 9 | 24 | 39 | 26 |

보스 보상은 `min(전설, 보스 티어)`를 최소 희귀도로 적용하고,
`18% + 티어 × 12%` 확률로 한 등급 승급한다. 보물은 26% 승급한다.
마지막에 플레이어 희귀도 편향을 더하고 일반~신화 범위로 제한한다.

## 4. 유물 결정 가중치

목표 희귀도에 유물이 없으면 높은 등급을 먼저 찾고, 없을 때 낮은 등급을 찾는다.
후보 안에서는 현재 술식·유물 태그 친화도를 반영한다.

```text
신규 유물 기본값 = 1.35
보유 유물 기본값 = 1.18
태그 일치 = min(1.8, 1 + 최고 친화도 × 0.12)
최종 가중치 = 기본값 × 태그 일치
```

아직 효과가 없는 `조련의 코어`는 길들인 보스 런타임이 구현되기 전까지 결과 풀에서
제외한다. 카탈로그와 도감에는 계속 남긴다.

## 5. Unity 목표 흐름

```text
보상 큐에 Relic(source, tier) 등록
→ 시간·출처·티어로 희귀도 결정
→ 태그 친화도로 유물 하나 결정
→ 18회 슬롯 순환 연출
→ 중복이면 레벨업
→ 빈 슬롯이면 장착
→ 가득 찼으면 최약 유물 자동 교체
→ 결과 카드와 실제 최종 효과 표시
→ 터치 또는 아무 키
→ 다음 FIFO 보상
```

최약 유물은 레벨이 낮은 항목을 우선하며, 레벨이 같으면 희귀도가 낮은 항목을 고른다.
교체할 때는 기존 유물의 레벨만큼 해제 효과를 반복 적용한 뒤 신규 유물을 LV.1로 장착한다.

## 6. UI 수용 기준

- 제목에서 `보스 유물 슬롯`과 `잭팟 유물 슬롯` 구분
- 검색 중에는 `SEARCHING RELIC`과 공명 주파수 안내
- 마지막 프레임에 희귀도·이름·다음 레벨 효과 표시
- 신규, 레벨업, 자동 교체 결과를 서로 다른 메시지로 표시
- 결과 카드가 닫히기 전에는 시간 정지와 활성 보상 유지
- 터치, 문자키, 숫자키 모두 동일한 결과 닫기 경로 사용
- 다음 보상은 결과 확인 뒤 1회만 열림
- 도감·메뉴·다른 선택 패널과 겹치지 않음

## 7. 자동 검증 수용 기준

Play Mode 스모크에 다음 결정론 검사를 추가한다.

1. 보스 티어 3 보상에서 목표 희귀도가 최소 전설인지 검사
2. 중복 유물이 정확히 한 레벨 증가하는지 검사
3. 빈 슬롯 장착 뒤 유물 수와 효과가 한 번만 증가하는지 검사
4. 가득 찬 슬롯에서 레벨 우선·희귀도 보조로 최약 항목이 교체되는지 검사
5. 결과 확인 전 `activeReward=Relic`, `timeScale=0` 유지
6. 결과 닫기 뒤 다음 FIFO 보상 한 개만 활성화
7. `tamer_core`가 비활성 콘텐츠 상태에서 추첨되지 않는지 검사

목표 표식:

```text
NEON_ARCANA_RELIC_FLOW_OK source=boss rarity=tiered roulette=18 award=automatic dismiss=required
```
